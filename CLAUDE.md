## Продукт

Приложение **не ставит диагнозы и не даёт медицинских рекомендаций**. Оно только напоминает и хранит данные. Это не меняем ни в коде, ни в текстах.

Фичи (модули):
1. **auth / profile**: email+пароль или Google, профиль, настройки уведомлений, вход по биометрии (опционально), язык.
2. **plan**: план профилактических осмотров. Справочник правил периодичности (терапевт, окулист, стоматолог, анализ крови…) сопоставляется с датами последних визитов. Статусы: `ok` («в порядке», зелёный), `soon` («скоро», жёлтый), `overdue` («просрочено», красный). **Индекс заботы** = доля пунктов плана в статусе `ok`, в процентах.
3. **visits**: журнал визитов (дата, врач/специальность, клиника, текст заключения, вложения фото/PDF), в хронологическом порядке.
4. **labs**: результаты анализов и графики динамики показателя с полосой референсного диапазона и отметкой отклонений.
5. **scan**: распознавание бланка по фото или PDF. Файл уходит в Supabase Edge Function, которая вызывает мультимодальную LLM и возвращает структурированный список показателей. Дальше **обязательный экран проверки**: неуверенные поля подсвечены, данные сохраняются только после подтверждения пользователем. Перед отправкой можно скрыть ФИО и дату рождения.
6. **meds**: лекарства и курсы (название, дозировка, время приёма, длительность), расписание на день, отметки приёма, прогресс курса.
7. **reminders**: локальные уведомления об осмотрах и приёмах лекарств, работают офлайн.
8. **summary**: сводка для врача в PDF (показатели, лекарства, состояние плана), отправка через share sheet.
9. **privacy**: экспорт всех данных пользователя в файл, полное удаление аккаунта.

Экраны по макету (390×844): 01 Приветствие, 02 Вход, 03 Главная, 04 План осмотров, 05 Журнал визитов, 06 Анализы, 07 Динамика показателя, 08 Сканирование бланка, 09 Проверка данных, 10 Новый визит, 11 Лекарства, 12 Сводка для врача, 13 Профиль и данные. Артборд «Прежний вариант C» устарел, не реализовывать.
Нижняя навигация: **Главная / План / Анализы / Лекарства / Профиль**.

## Стек

- **Flutter**, Dart. Целевая платформа: Android, minSdk 26. iOS пока не поддерживаем, но платформенно-зависимый код держим изолированным.
- Состояние и DI: **Riverpod** с кодогенерацией (`riverpod_annotation`, `riverpod_generator`). Bloc и get_it **не использовать**.
- Модели: **freezed** + **json_serializable**.
- Навигация: **go_router** с `StatefulShellRoute` для нижней навигации и redirect неавторизованных на экран входа.
- Backend: **Supabase**: Auth, PostgreSQL с RLS, Storage, Edge Functions (Deno/TypeScript).
- Уведомления: `flutter_local_notifications` + `timezone`. Push/FCM не нужны.
- Графики: `fl_chart`. PDF: `pdf` + `printing`, шаринг: `share_plus`.
- Файлы: `image_picker`, `file_picker`.
- Безопасность: `local_auth`, `flutter_secure_storage`. Простые настройки: `shared_preferences`.
- UI: Material 3, `google_fonts` (Manrope), анимации **Rive** (приветствие, кольцо индекса заботы).
- Локализация: `flutter_localizations` + `intl` (ARB), языки **ru** (основной) и **ro**.
- Тесты: `flutter_test`, `mocktail`. Линтер: `flutter_lints`.

Новые зависимости добавлять только при реальной необходимости, предпочтительно open-source и бесплатные.

## Архитектура

Clean Architecture + MVVM, код разбит по фичам:

```
lib/
  main.dart
  app/                 # App widget, router, theme, l10n setup
  core/                # общие утилиты, ошибки (Failure), extensions, supabase client provider, widgets
  features/
    <feature>/         # auth, profile, plan, visits, labs, scan, meds, reminders, summary
      data/            # DTO, datasources (Supabase), repository impl
      domain/          # entities, repository interfaces, use cases (чистый Dart, без Flutter/Supabase)
      presentation/    # screens, widgets, Riverpod notifiers (ViewModel)
  l10n/                # app_ru.arb, app_ro.arb
supabase/
  migrations/          # SQL-миграции (схема + RLS)
  functions/           # Edge Functions (recognize-lab-form и др.)
test/                  # зеркалит структуру lib/
```

Правила:
- `domain` не импортирует Flutter, Supabase и пакеты `data`/`presentation`.
- Состояние экранов через `AsyncValue` / sealed freezed-состояния (loading / data / error).
- Бизнес-логику (расчёт статусов плана, индекса заботы, расписания приёмов, отклонений от нормы) держим в `domain` как чистые функции/use cases и **покрываем unit-тестами**.
- Даты храним в UTC, в UI переводим в локальное время. Уведомления планируем через `timezone`.

## Безопасность и данные (обязательно)

- **RLS включён на каждой таблице** с пользовательскими данными. Политики `user_id = auth.uid()` на select/insert/update/delete. Storage-бакеты приватные, путь `<user_id>/...` с соответствующими политиками.
- **Никаких секретов в клиенте.** В приложении только Supabase URL и anon key. Ключ LLM живёт только в секретах Edge Function.
- Не логировать медицинские данные и персональные данные (print/debugPrint/аналитика).
- Распознанные значения сохраняются в БД **только после подтверждения** на экране проверки.
- Валидация ввода на клиенте, права проверяет сервер (RLS).
- Офлайн: кэшировать последние загруженные данные, показывать понятные ошибки. Напоминания работают без сети.
- Экспорт данных и удаление аккаунта должны охватывать все таблицы и файлы в Storage.
- Секреты (`.env`, ключи) не коммитить. Конфиг Supabase передавать через `--dart-define` или `.env` из `.gitignore`.

## Дизайн-система (из макетов)

- Шрифт **Manrope** (500–800). Заголовки 800, letter-spacing −0.01em.
- Фон экрана `#E9EFFB`. Основной текст `#0B1736`, вторичный `#46577A`, ссылки/акцент `#1F5FBF`.
- Фирменный градиент (шапка, акцентные карточки, активная вкладка): `#051642 → #123A96 → #2F6BDA` (150°). Доп. акценты: `#5EC8F2` (голубой), `#8B7CFF` (фиолетовый, декоративные пятна), золото `#F3E2B3 → #C9A45C` (рамка аватара).
- Статусы (фон / текст):
  - в порядке: `#DDF3E6` / `#0F6A3D`
  - скоро: `#FFEFCB` / `#7A4D00`
  - просрочено: `#FDE4E2` / `#B3261E`
- «Стеклянные» карточки: белый 86→60% с blur, белая рамка, мягкая синяя тень, радиус 26–30. Шапка с нижним радиусом 40.
- Плавающая нижняя навигация: высота 70, радиус 35, отступ 14 от краёв.
- Цвета, радиусы и отступы задаются **через тему/токены** (`ThemeExtension`), не хардкодом в виджетах.
- Доступность: touch targets ≥ 44px, контраст текста ≥ 4.5:1, `Semantics` для иконок-кнопок, статус передаётся не только цветом (иконка + текст). Уважать reduce-motion.

Перед версткой экрана читать соответствующий `project/NN-*.dc.html` с холста и повторять его структуру и тексты.
